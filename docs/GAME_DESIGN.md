# 신발을 찾아서 — GAME DESIGN

> 플랫폼: `오락실 이안월드` (다중 게임 포털) / 1번 게임: **신발을 찾아서**
> 문서 버전: v0.1 (기획 확정 전, `[빈칸]` = 사용자 결정 필요)
> 최종 수정: 2026-08-13

---

## 0. 문서 사용법

- `[빈칸]` 은 **사용자가 결정해야 하는 값**입니다. 코드 작성 전 반드시 채웁니다.
- 숫자는 전부 **논리 픽셀(dot)** 또는 **초(sec)** 단위입니다.
- 이 문서가 유일한 진실(single source of truth)입니다. 코드와 충돌하면 이 문서를 먼저 고칩니다.

## 1. 한 줄 정의

> **맨발의 주인공이 신발 상자 계단을 좌우로 오르며, 밟는 순간 신발을 갈아 신고, 130종 신발 도감과 명예의 전당을 채워가는 세로형 레트로 도트 아케이드 게임.**

- 원형(reference): 「무한의 계단」
- 차별점: ① 계단이 **신발 상자**다 ② 밟으면 **신발을 신는다** ③ **130종 신발 도감** ④ 신발이 **캐릭터 구매 재화**이자 **멀티플레이 베팅 재화**

---

## 2. 핵심 재미 (한 가지)

> **"다음 칸에 어떤 신발이 있을까?"** — 목숨 걸고 빨리 올라갈수록 더 많은, 더 높은 티어의 신발을 줍는다.

계단 오르기는 수단이고, **수집**이 목적이다. 점수(계단 수)는 명예의 전당용, 신발 수는 자산이다.

---

## 3. 핵심 루프

### 3-0. 게임 시작 연출 (2026-08-14 추가)

플레이어는 **첫 계단 한 칸 아래 도로**에서 시작한다. 이미 계단 위에 서 있으면 "출발하는 느낌"이 없다.

```
① 정면 컷으로 0.5초 (30프레임) 정지          ← 플레이어를 보여준다
② 1.2배로 커졌다가 (5프레임) 원래대로 (4프레임)  ← "준비!"
③ 0.3초 (18프레임) 대기
④ 첫 계단 방향으로 고개를 돌린다 → 조작 가능
```
- 총 57프레임 ≈ 0.95초. 이 동안 **입력은 무시되고 시간 게이지도 줄지 않는다.**
- 게이지는 인트로가 끝난 뒤 **첫 입력**부터 감소를 시작한다.

### 3-1. 매 초 루프 (In-Game Loop)

```
① 다음 계단의 방향을 본다 (왼쪽 위 / 오른쪽 위)
② 지금 보는 방향과 같으면 [상승], 다르면 [방향전환] — 둘 다 한 칸 올라간다
③ 캐릭터가 1칸 오른다  → 이펙트 컷(번개) **3프레임(0.05초)** → 방향 컷
   · 계단 이동은 **즉시 스냅**. 스텝 상승 연출은 넣었다가 리듬을 죽여서 제거했다.
   · 이펙트 재생 중에도 전환·상승 입력을 즉시 받는다 (막으면 "착착착" 리듬이 끊긴다)
   · 이 게임의 핵심은 **빠르게 착착착 올라가는 리듬**이다. 연출이 길면 무조건 방해가 된다.
   · 배경이 정확히 계단 1칸 높이만큼 아래로 스크롤
   · 시간 게이지 소폭 회복 · 계단 카운터 +1
④ 그 칸에 신발이 있으면 → 신발 착용(교체) · 도감 등록 · 획득 효과음 · 신발 1.1배 팝
⑤ 시간 게이지는 계속 줄어들고, 층수가 올라갈수록 더 빨리 줄어든다
⑥ 방향을 틀리면 → 정면 컷 → 살짝 커짐 → 신발이 좌우로 튕겨나감 → 맨발로 낙하 → GAME OVER
   (부활 보유 시: 부활 사용 여부 선택)
```

### 3-2. 메타 루프 (Meta Loop)

```
게임 종료 → 신발/기록 저장 → 로비
  ├─ 도감 확인 (130종 중 몇 개?)
  ├─ 신발로 잠금 캐릭터 구매 (신발 차감 → 신발왕 순위 하락)
  ├─ 명예의 전당 확인 (계단왕 / 신발왕)
  └─ 멀티 도전 (이기면 신발 강탈, 지면 1켤레 상납)
      → 다시 싱글로 신발 보충
```

## 4. 조작표

### 4-1. 입력 장치

- 모바일 세로 화면, **양손 엄지 2버튼**
- 화면 하단 좌·우 대형 버튼 (레퍼런스: `etc/시작인터페이스.png`)
- 데스크톱 테스트용 키보드 매핑: `←` = 좌버튼, `→` = 우버튼, `Space` = 우버튼

### 4-2. 조작 모드 (로비 → "조작법 변경" 에서 순환 전환)

| # | 모드명 | 좌측 버튼 | 우측 버튼 | 아이콘 |
|---|--------|-----------|-----------|--------|
| 1 | **전환–상승** (기본) | 방향 전환 | 상승 | 순환화살표 / 삼각형 |
| 2 | **상승–전환** | 상승 | 방향 전환 | 삼각형 / 순환화살표 |
| 3 | **좌상승–우상승** | 왼쪽 위로 상승 | 오른쪽 위로 상승 | 좌상향 / 우상향 |

> 아이콘 원본: `etc/인터페이스 버튼.png` → `tools/slice-buttons.mjs` 가
> `public/assets/ui/btn_{turn,up,left,right}.png` (각 **48 × 48**) 로 잘라낸다.
> 레퍼런스 실측: 버튼 220×225px = 47×48 논리px, 위치 y 266~315.
> 원본이 매끈한 렌더라 배경 키잉 → lanczos 축소 → 16색 양자화로 도트화한다.
> 세 모드 모두 **1탭 = 1칸 상승**이다. 모드 3은 "다음 계단이 왼쪽이면 좌버튼, 오른쪽이면 우버튼"으로
> 모드 1·2와 결과가 같고 표현만 다르다.

### 4-3. 판정

**핵심: 두 버튼 모두 한 칸 올라간다.** (2026-08-14 수정 — 「무한의 계단」과 동일한 방식)

| 버튼 | 동작 |
|------|------|
| **[상승]** | 지금 보는 방향 **그대로** 한 칸 올라간다 |
| **[방향전환]** | 방향을 **반대로 바꾸면서** 한 칸 올라간다 |

즉 매 순간 둘 중 **하나만 정답**이고, 틀린 쪽을 누르면 그 방향을 본 채로 추락한다.
전환 버튼이 제자리에서 방향만 바꾸면 한 칸 오르는 데 두 번 눌러야 해서 "착착착" 리듬이 죽는다.

| 상황 | 결과 |
|------|------|
| 누른 버튼이 만드는 방향 == 다음 계단 방향 | 정상 상승 (+1칸, 게이지 회복) |
| 누른 버튼이 만드는 방향 != 다음 계단 방향 | **추락 사망** |
| 입력 없음 | 게이지만 감소 |
| 버튼 연타 | 큐에 최대 2입력까지 버퍼링 (그 이상은 무시) |
| 이펙트 컷 재생 중 입력 | **즉시 처리** — 막으면 리듬이 끊긴다 |

## 5. 점수 · 수치 공식

### 5-1. 계단 점수

```
STAIR_SCORE = 올라간 칸 수 (1칸 = 1점)
```
- 상단 중앙에 대형 숫자로 표시 (레퍼런스: `etc/게임인터페이스.png` 의 "26")
- 명예의 전당 "계단왕" 랭킹의 기준값

### 5-2. 신발 카운터

```
SHOES_FOUND (이번 판)   = 이번 판에서 밟은 신발 칸 수      → 좌상단 "찾은신발 N"
SHOES_OWNED (계정 자산)  = 누적 획득 - 캐릭터 구매 차감 - 멀티 패배 차감 + 멀티 승리 강탈
DEX_UNIQUE              = 도감에 등록된 고유 신발 종류 수 (0~130, 절대 감소 없음)
```
> **중요**: 도감(`DEX_UNIQUE`)은 한 번 찾으면 영구 보존. 캐릭터 구매로 차감되는 것은 **자산 수량(`SHOES_OWNED`)** 뿐입니다.

### 5-3. 시간 게이지 (Time Gauge)

```
GAUGE_MAX = 100

drain(floor) = min( DRAIN_BASE + DRAIN_GROWTH × floor , DRAIN_CAP )   [단위: 게이지/초]
계단 1칸 상승 시:  gauge = min(GAUGE_MAX, gauge + STEP_REWARD)
신발 획득 시:      gauge = min(GAUGE_MAX, gauge + SHOE_REWARD)
gauge <= 0        → 사망 (시간 초과)
```

**튜닝 방향 (확정): 「무한의 계단」보다 살짝 빡세게.**

| 난이도 | DRAIN_BASE | DRAIN_GROWTH | DRAIN_CAP | STEP_REWARD | SHOE_REWARD |
|--------|-----------|--------------|-----------|-------------|-------------|
| 쉬움 (느림)     | **11.0** /s | **+0.035** /칸 | **24** /s | **+7.0** | +8 |
| 보통            | **16.0** /s | **+0.060** /칸 | **31** /s | **+6.0** | +8 |
| 어려움 (초스피드) | **20.0** /s | **+0.095** /칸 | **36** /s | **+5.5** | +8 |

**실효 요구 속도** — 신발 회복(+8)까지 포함한 "실제로 눌러야 하는 초당 칸 수"

```
실효 회복량 = STEP_REWARD + 8 / (신발 평균 간격)
요구 속도  = drain(floor) / 실효 회복량
```

| 난이도 | 신발 평균 간격 | 실효 회복량 | 0층 요구 | 100층 | 250층 | 캡 도달 이후 |
|--------|---------------|------------|---------|-------|-------|-------------|
| 쉬움   | 15칸 | 7.53 | **1.46칸/s** | 1.93 | 2.55 | 3.19칸/s (686층~) |
| 보통   | 6.5칸 | 7.23 | **2.21칸/s** | 3.05 | 4.29 | 4.29칸/s (250층~) |
| 어려움 | 4.5칸 | 7.28 | **2.75칸/s** | 4.05 | 4.95 | 4.95칸/s (168층~) |

**설계 의도**
- 「무한의 계단」 초반 체감이 대략 초당 2칸이었다면, 이 게임의 **보통은 2.2칸 / 어려움은 2.75칸**으로 시작부터 손을 쉬게 두지 않는다.
- **가속이 더 가파르다.** 보통은 250층, 어려움은 168층이면 이미 최고 속도에 도달한다. 원작처럼 "천천히 조여오는" 게 아니라 **초중반에 확 조인다.**
- 그 대신 **캡을 사람이 칠 수 있는 선(초당 4.3~5.0칸)에 둔다.** 그 위는 실력이 아니라 손가락 물리 한계라 재미가 없다. 400층 이상은 "속도"가 아니라 **집중력 유지 싸움**으로 만든다.
- **어려움이 오히려 오래 못 간다.** 168층에서 캡이라 기록은 낮게 나오지만 신발은 4.5칸마다 쏟아진다 → **어려움 = 신발 파밍 모드, 쉬움 = 기록 도전 모드.** 랭킹이 난이도별로 분리되어 있어 이 구조가 성립한다.
- 부활은 신발 50개당 1개(2026-08-15 개정, 이전 20개) → 어려움에서 가장 잘 쌓인다. 극한 구간에서 실수 1~2번을 사주는 완충재.

**아이들 사망 시간** (아무것도 안 눌렀을 때 0층 기준): 쉬움 9.1초 / 보통 6.3초 / 어려움 5.0초

> 이 수치는 전부 `src/config/balance.js` 한 파일에만 존재한다. 플레이 테스트 후 그 파일만 고친다.

### 5-4. 신발 등장 빈도 (칸 간격, 균등 랜덤)

| 빈도명 | 간격 | 싱글 난이도 매핑 | 멀티 |
|--------|------|------------------|------|
| 흔함 | 3~6칸마다 1개 | **어려움** | 방장 선택 |
| 보통 | 4~9칸마다 1개 | **보통** | 방장 선택 |
| 희귀 | 10~20칸마다 1개 | **쉬움** | 방장 선택 |

> 원문에 "희귀"가 두 번 적혀 있어 중간 단계를 **보통(4~9칸)** 으로 정정했습니다.

### 5-5. 신발 티어 (아틀라스 `sneaker_strata_spec_sheet` 기준 확정)

| 티어 | 명칭 | 종류 수 | 등장 확률 | 색 규칙 |
|------|------|---------|-----------|---------|
| 1티어 | MAXIMAL CHROMA | 5종 | **5%** | 완전 화려한 다색 |
| 2티어 | BLOCKED COLOUR | 10종 | **10%** | 4색 블록 |
| 3티어 | PATTERN + CONTRAST | 15종 | **15%** | 3색 + 패턴 |
| 4티어 | TWO-TONE CLASSIC | 40종 | **20%** | 2색 |
| 5티어 | SINGLE PIGMENT | 60종 | **50%** | 단색 |
| **합계** | | **130종** | **100%** | |

> 원문의 "2가지색은 2티어(20%)" 는 개수·색 규칙상 **4티어**의 오기로 판단해 정정했습니다.

**티어 롤 방식** (확정):

```
① 위 확률표로 티어 결정 (T1 5% / T2 10% / T3 15% / T4 20% / T5 50%)
② 해당 티어 안에서 완전 균등 랜덤으로 종류 결정
```

- **도감 보유 여부는 확률에 전혀 영향을 주지 않는다.** 미보유 신발에 가중치를 주지 않는다.
- 이유: 확률이 정직해야 "1티어를 뽑았다"가 진짜 운으로 느껴진다. 보정이 들어가면 도감이 찰수록 뽑기가 쉬워져 후반 희소성이 무너진다.
- 결과적으로 도감 완성은 **쿠폰 수집가 문제(coupon collector)** 가 된다. 티어별 기대 시행 횟수:

| 티어 | 종류 | 등장 확률 | 전종 수집 기대 획득 수 |
|------|------|-----------|----------------------|
| T1 | 5종 | 5% | 약 228켤레 |
| T2 | 10종 | 10% | 약 293켤레 |
| T3 | 15종 | 15% | 약 340켤레 |
| T4 | 40종 | 20% | 약 863켤레 |
| T5 | 60종 | 50% | 약 561켤레 |
| **전체 130종** | | | **약 870켤레** (T4가 병목) |

> 130종 완주에 누적 약 870켤레가 필요하다. 어려움 난이도(4.5칸당 1켤레)로 100층을 오르면 약 22켤레 →
> **대략 40판** 정도의 장기 목표. 캐릭터 구매(최대 130켤레)와 멀티 손실을 감안하면 더 길어진다. 의도된 길이다.

### 5-6. 부활 (싱글 전용)

```
이번 판 신발 20개 획득마다 부활 +1 (판 종료 시 소멸)
사망 시 부활 보유 → "부활하시겠습니까?" 10초 카운트다운 → 사용 시 gauge = 100, 같은 칸에서 재개
멀티플레이: 부활 없음
```
- 표시 위치: 우상단 일시정지 버튼 바로 아래 `부활 1`
- 카운트다운은 **10초** (2026-08-14 개정 — 3초는 죽는 순간의 놀람 때문에 하트를 누를 틈이 없었다)

### 5-7. 멀티플레이 정산

| 인원 | 1등 보상 | 나머지 |
|------|----------|--------|
| 2인 | +1켤레 | 각 -1켤레 |
| 3인 | +2켤레 | 각 -1켤레 |
| 4인 | +3켤레 | 각 -1켤레 |

- 승자 메시지: `1등을 하셨습니다` / `게임의 승리로 N켤레의 신발을 뺏어왔습니다`
- 패자 메시지: `내 소중한 신발 1켤레를 뺏겼습니다`
- 참가 조건: `SHOES_OWNED >= 2` (1켤레 이하 참가 불가)
  - 차단 메시지: `신발이 1켤레 이하면 게임에 참가할 수 없습니다 / 신발을 모아서 게임에 참여하세요`
- 종료 조건: **누구든 1명이 사망하는 즉시 전원 종료**
- 순위 기준: **획득 신발 수** (동률 시 계단 수, 그래도 동률이면 먼저 도달한 사람)
- 빼앗기는 신발 선택 규칙: **랜덤** (보유 수량 기준 균등 추첨. 티어 무관)
  - 도감(`DEX_UNIQUE`)은 감소하지 않는다. 수량만 이동한다.
  - 승자에게는 패자에게서 뽑힌 신발이 그대로 들어가고, 승자 도감에 없던 종류면 **도감에도 신규 등록**된다.

### 5-8. 캐릭터 잠금 해제 비용

| 순서 | 캐릭터 | 해금 조건 |
|------|--------|-----------|
| 1 | 이안 (메인) | 무료 |
| 2 | 데니 | 무료 |
| 3 | 리사 | 무료 |
| 4 | 이포 | 무료 |
| 5 | 찰스 | 무료 |
| 6 | 경태 | 신발 10켤레 |
| 7 | 마호 | 신발 20켤레 |
| 8 | 토니 | 신발 50켤레 |
| 9 | 제니 | 신발 100켤레 |
| 10 | 로제 | 신발 130켤레 |

- 잠금 캐릭터는 **회색 실루엣**으로만 표시 (생김새 비공개 = 궁금증 유발)
- `[SELECT]` 버튼 비활성 + 하단에 `* 신발 10개 필요 *`
- 대신 `[캐릭터 구매하기]` 버튼 노출, 보유 신발 충분 시에만 활성
- 구매 확인 다이얼로그 문구: `티어가 높은 신발부터 사라집니다`
- 차감 규칙: **1티어 → 2 → 3 → 4 → 5 순으로 소진** (도감 기록은 유지, 수량만 감소)

### 5-8-1. 엘리베이터 (500층 스킵) — 2026-08-14 추가

500층을 한 번이라도 밟아 본 계정에게 열리는 **숏컷**이다.
아래층 반복이 지겨워진 고수가 곧장 신기록 구간부터 시작할 수 있게 하되,
보유 신발을 태워야 하므로 남발할 수는 없다.

```
해금 조건 : bestStairs >= 500  (역대 최고 기록, 난이도 무관 — 한 번 해금되면 영구)
사용 위치 : 게임 로비(S04) — [싱글게임] 옆 [🛗 엘리베이터] 버튼
비용     : 1회 사용당 신발 50켤레 차감
효과     : 시작 층수 = 500층 (floor = 500), 그 외 모든 규칙은 일반 싱글과 동일
```

| 항목 | 규칙 |
|------|------|
| 버튼 노출 | `bestStairs >= 500` 일 때만 로비에 나타난다. 미달이면 아예 그리지 않는다 |
| 버튼 활성 | `shoesOwned >= 50` 일 때만 활성. 부족하면 비활성 + `* 신발 50켤레 필요 *` |
| 확인 다이얼로그 | `엘리베이터를 타고 500층부터 시작합니다` / `신발 50켤레가 사라집니다` / `티어가 높은 신발부터 사라집니다` |
| 차감 규칙 | 캐릭터 구매와 **동일** — 1티어 → 2 → 3 → 4 → 5 순으로 50켤레 소진. 도감(`DEX_UNIQUE`)은 감소하지 않는다 |
| 차감 시점 | 다이얼로그 확인 **즉시** 차감하고 게임을 시작한다. 도중에 나가도 환불 없음 |
| 시작 상태 | `floor = 500`, 게이지 100%, 부활 0, 배경은 §9-5의 `floor500` |
| 난이도 | 로비에서 선택한 난이도를 그대로 쓴다. 게이지 감소율은 §6 곡선의 **500층 값**부터 시작 |
| 점수 처리 | 랭킹에 **정상 제출**한다. 500층을 밟는 데 이미 실력을 증명했고, 비용도 지불했다 |
| 멀티 | **사용 불가.** 멀티는 항상 1층에서 동시 출발한다 (시드 동기화 전제) |
| 신발 카운터 | 이번 판 획득 신발은 평소대로 누적된다 (엘리베이터 비용과 별개) |

- 로비 문구: `500층 이상 도달 시 이용할 수 있습니다`
- 사용 로그: `users/{uid}.elevatorUses` 를 +1 (통계용)

### 5-9. 명예의 전당

| 탭 | 랭킹 기준 | 난이도 분리 |
|----|-----------|-------------|
| 신발왕 | `SHOES_OWNED` 보유 수량 (티어 무관) | 없음 (통합 1개) |

- 표시 인원: 상위 **100명** + 항상 하단에 "내 순위" 고정 행
- 집계 문서 키: `leaderboards/{period}_{difficulty}` (예: `weekly_hard`) + `leaderboards/shoeking`

## 6. 난이도 곡선

```
층수      0 ─────── 100 ─────── 200 ─────── 300 ─────── 400 ─────── 500+
게이지    느림 ───────────────── 점점 빨라짐 ──────────── 캡(고정 최고속)
배경      건물 16종 랜덤 1개 반복
구름                ★구름 등장
배경교체                     200층↑     300층↑     400층↑     500층↑
BGM       트랙1  트랙2  트랙3  트랙4  트랙5  트랙6  트랙7  트랙8  트랙9  트랙10
          (100층마다 다음 트랙 · 뒤로 갈수록 BPM ↑ · 트랙10 이후는 트랙10 유지)
```

| 구간 | 체감 (보통 기준) |
|------|------|
| 0~30층 | 시작부터 초당 2.2칸. 튜토리얼 없이 바로 조인다 |
| 30~100층 | 리듬 타기 시작. 첫 부활(신발 20개) 획득 지점 |
| 100~200층 | 구름 등장 = "높이 왔다" 보상감. 요구 속도 3.0 → 3.9칸/s |
| 200~250층 | **가속 종료.** 캡(4.29칸/s) 도달. 여기까지가 실력 구간 |
| 250층+ | 속도는 더 안 오른다. **집중력 유지 싸움.** 배경이 100층마다 바뀌며 버티게 한다 |
| 400~500층+ | 실수 1번 = 종료. 부활 잔량이 곧 남은 목숨 |

> 어려움은 168층에서, 쉬움은 686층에서 캡에 도달한다. 즉 **난이도를 바꾸면 "실력 구간의 길이"가 바뀐다.**

**난이도 선택 (로비)** — 표기: `게임난이도(신발의 등장 빈도가 달라집니다)`

| 버튼 | 실제 효과 |
|------|-----------|
| 쉬움 | 게이지 느림 + 신발 희귀(10~20칸) |
| 보통 | 게이지 보통 + 신발 보통(4~9칸) |
| 어려움 | 게이지 초스피드 + 신발 흔함(3~6칸) |

> 즉 **"빨리 죽을 각오를 하면 신발을 더 많이 얻는다"** 는 리스크–리워드 구조.
> 명예의 전당은 **난이도별 3개 랭킹으로 분리** (쉬움/보통/어려움). 쉬움에서 나온 계단 수가 어려움 랭킹을 오염시키지 않는다.

#### 9-3-1. 착용 신발 — 맨발이 1도트도 보이면 안 된다 (2026-08-15 확정)

신발을 신었는데 발등·발목이 비치는 건 **버그**다. 신발 스프라이트로 발을 "덮는" 방식은
신발 실루엣이 발보다 낮거나 좁으면 반드시 삐져나온다(로우컷·슬리퍼). 그래서 반대로 간다:

```
신발을 신고 있으면 캐릭터 컷의 맨발 영역을 아예 그리지 않는다.
```

- 발이 시작하는 행은 슬라이서가 **살색 판정**으로 컷마다 측정한다
  (`tools/slice-characters.mjs footAnchor()` → `characters.generated.json` 의 `cuts[*].foot.top`).
  얼굴에서 살색을 뽑고, 아래에서 위로 "그 행 불투명 픽셀의 과반이 살색"인 동안을 발로 본다.
  맨다리 캐릭터(치마·반바지)가 무릎까지 올라가지 않도록 **아래 5~9행으로 클램프**한다.
- 런타임은 `min(foot.top, 원본높이 - 7)` 행부터 아래를 잘라내고 그린다 — 최소 7행은 무조건 자른다.
- 잘린 단면은 신발이 더 위(밑창 기준 19도트)에서 시작하므로 항상 가려진다.
- 신발 좌우 위치는 `cuts[*].foot.cx` 를 캐릭터 배율(1.5)로 환산해 맞춘다.
- **외곽선 1도트(진회색 `#3A3A42`)** 를 둘러 캐릭터 위에 얹혀도 "장착된" 것처럼 또렷하게 보인다.
- 크기는 이전(28×17)의 약 **1.1배**. 신발 찾기 게임이므로 신발이 확실히 눈에 띄어야 한다.

**신발 방향** — 아틀라스 원본은 **오른쪽을 향한다** (뒤꿈치가 왼쪽).
따라서 오른쪽 계단은 그대로, **왼쪽 계단일 때만 좌우 반전**한다. 착용 신발도 동일 규칙.
이렇게 하면 밟는 순간 그 신발이 향하던 방향 그대로 신고 올라가는 것처럼 보인다.

- 세로 30은 **최대값**이다. 농구화·부츠처럼 발목까지 오는 신발만 30을 꽉 채우고,
  스니커즈는 ~20, 슬리퍼는 ~12처럼 낮게 그린다. **모든 컷은 바닥 정렬.**
- 계단 블록이 24×10이므로 계단용 25×15는 블록보다 1px 넓다 — 상자 위에 얹힌 느낌으로 딱 좋다.
- 착용용 15×9는 근사 축소라 품질이 떨어지면 플레이 테스트 후 20×12(0.4배) 또는 계단용(25×15) 재사용으로 조정한다.

**도감(S06) 확대 규칙** — 도감은 DOM 화면이므로 논리 해상도 제약이 없다.

| 화면 | 표시 |
|------|------|
| 도감 목록 그리드 | 마스터 1×~2× (`image-rendering: pixelated`) |
| **신발 탭 → 상세 팝업** | **마스터 3×~4× (150×90~200×120)** + 신발 이름, 티어, 최초 획득일, 누적 획득 수 |

**마스터 아틀라스**

| 항목 | 값 |
|------|-----|
| 셀 | 52 × 32 (신발 50×30 + 여백 2px) |
| 배치 | 10열 × 13행 = 130칸, 행 우선 |
| 아틀라스 | **520 × 416**, RGBA |
| 인덱싱 | 0~4 = T1, 5~14 = T2, 15~29 = T3, 30~69 = T4, 70~129 = T5 |
| 파생 아틀라스 | 계단용 260×208 (셀 26×16) · 착용용 160×130 (셀 16×10) — 빌드 타임 자동 생성 |

**소스 상태 (✅ 최종, 4차)**: 사용자 제공 아트 시트 `etc/신발자료/newdesign.png` 를
`tools/slice-newdesign.mjs` 가 슬라이스한다. 원본은 픽셀아트풍 렌더링(안티앨리어싱 56%)이라
그대로 자르지 않고 **블롭 검출 → 배경 키잉 → 50×30 이내 축소(lanczos) → 신발당 14색 양자화**로
도트화한다. 결과물은 정수배 확대 시 완전한 픽셀 퍼펙트. 136개 블롭 중 130개 사용.

**티어 배정은 "화려할수록 높은 티어" 규칙으로 자동 랭킹**: 신발별 화려함 점수
(색상 다양성 ×3 + 고유 색 수 ×0.35 + 평균 채도 ×6)를 매겨 상위 5 = T1, 다음 10 = T2,
다음 15 = T3, 다음 40 = T4, 나머지 60 = T5.

시트를 교체·수정하면 `npm run assets:shoes` 재실행으로 전체 파이프라인이 재생성된다.
(이전 코드 생성기 `tools/generate-shoes.mjs` 는 폴백으로 저장소에 남겨둔다)

|------|-----|
| 서체 | Galmuri11 Bold — quiple 제작, **SIL Open Font License 1.1** (상업·무료 모두 허용) |
| 글리프 상자 | **11px 높이**, 숫자 폭 8px (`1`만 5px) |
| 획 굵기 | 2도트 — 배경이 복잡해도 묻히지 않는다 |
| 조달 | npm `galmuri` 패키지의 `Galmuri11-Bold.ttf` |
| 굽는 법 | `npm run assets:font` → `tools/build-font.mjs` 가 TTF 아웃라인을 픽셀 격자로 굳혀 `src/data/font.generated.json` (비트마스크) 생성 |

**왜 TTF를 런타임에 안 쓰나**: `ctx.fillText` 는 어떤 설정으로도 안티앨리어싱을 끌 수 없다.
빌드 타임에 도트로 굳혀 두면 색·외곽선·그림자를 자유롭게 주면서 배율은 정수로만 곱해져 항상 픽셀 퍼펙트다.

> 참고: 「무한의 계단」이 쓴 서체는 공개된 자료가 없다. 스크린샷 실측상 **7×11 굵은 둥근 도트에
> 크림색 글자 + 진한 갈색 외곽선**이며, 갈무리11 볼드가 굵기·비율·둥근 정도에서 가장 가깝다.
> 갈무리는 한글 글리프도 있어 M5의 로비/도감 화면까지 같은 서체로 통일할 수 있다.

### 9-6-2. HUD 숫자 배치 — **행 분리 원칙**

계단 수가 3~4자리, 신발이 2자리가 되면 예전 배치에서 글자가 겹쳤다.
자릿수는 계속 늘어나므로 "폭을 계산해 피하는" 방식은 언젠가 또 깨진다 →
**y로 행을 완전히 분리**해 몇 자리가 되든 물리적으로 겹칠 수 없게 한다.

| y 범위 | 내용 | 크기 |
|--------|------|------|
| 3~21 | 시간 게이지 (좌) + 일시정지 버튼 (우) | 146×18 / 18×18 |
| 23~38 | 신발 아이콘 + 획득 수(좌) · 하트 + 부활 수(우) | 폰트 **×1** (11px) |
| 41~63 | 계단 수 (가운데) | 폰트 **×2** (한 자리 14×22) |

**게이지 구조** (사용자 아트 `etc/게이지바.png` 의 동심 라운드 사각형을 그대로 도트화):
`딥레드 테두리 1도트 → 크림 띠 2도트(위 하이라이트 · 아래 그늘) → 안쪽 딥레드 1도트 → 트랙`
채움 영역은 프레임 안쪽 (8, 7, 138×10). 채움색 `#CD4421`, 30% 미만이면 경고색 `#F2C23C`.
프레임만 스프라이트고 **채움은 런타임 사각형**이라 어떤 비율에서도 도트가 깨지지 않는다.

- 계단 수는 **고정폭(mono)** 으로 찍는다 — `1` 이 섞여도 가운데 정렬이 흔들리지 않는다.
- 계단 수 크기는 `layout.js` 의 `HUD.score.scale` 하나로 바꾼다 (2 = 22px / 3 = 33px).
  ×2가 레퍼런스 「무한의 계단」 실측(≈15×22)과 거의 같다.

#### 9-7-1. `sfx_shout` — 칩튠 함성 설계

80~90년대 아케이드 기판은 사람 목소리를 낼 수 없어서 **"목소리처럼 들리는 파형"** 으로 흉내 냈다. 그 기법을 그대로 쓴다.

```
구성 (총 90~120ms)
① 어택   : 화이트 노이즈 20ms, 하이패스 2kHz → "츠" (숨 들어가는 소리)
② 보디   : square 파형 + 빠른 피치 벤드 (하강 후 살짝 상승)
           예) 440Hz → 300Hz → 360Hz  ("어–어–엇" 형태의 모음 굴곡)
③ 포먼트 : BiquadFilter bandpass 2개를 직렬 연결
           F1 ≈ 700Hz (Q 5) / F2 ≈ 1200Hz (Q 8)  ← "아" 모음의 포먼트
           F2를 1200 → 1800Hz로 스윕하면 "아→에" 처럼 들린다
④ 비브라토: LFO 6Hz, 깊이 ±12 cents (사람 목소리의 떨림)
⑤ 엔벨로프: attack 5ms / decay 30ms / release 60ms, 끝을 뚝 자른다
```

- 캐릭터마다 **기본 피치를 다르게** 준다 (남성형 ×0.85 / 여성형 ×1.20 / 이포 ×1.35) → 10명이 각자 다른 목소리로 들린다.
- 연발 방지: 최소 간격 250ms. 그보다 빨리 밟으면 `sfx_step` 만 나가고 함성은 생략한다.
- 발동 조건: `[빈칸 아님 — 확정]` **3연속 무실수 상승마다 1회** + **1·2티어 신발 획득 시 무조건**. 매 칸마다 지르면 시끄럽다.
- 비교 레퍼런스 감각: 「스트리트 파이터 II」의 "허리켄", 「파이널 파이트」의 타격 보이스처럼 **알아들을 수 없지만 사람 같은** 소리가 목표다.

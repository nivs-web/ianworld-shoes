# 멀티플레이 역전 배틀 — 구상 및 실현 가능성 검토 (2026-08-18)

> 요청 요약: ① 상대가 올라가는 걸 **눈으로** 보게 하고 ② 상대 아이디는 **작은 글씨 + 캐릭터 아이콘**,
> ③ 죽으면 즉시 끝나지 않고 **20초 안에 신발 20켤레를 걸고 1위보다 20칸 앞에서 부활**,
> ④ 화면 하단에 **"이 게임에 걸린 신발 N켤레"**, ⑤ 최종 승자가 **판돈 전부** 수거,
> ⑥ 낙사·부활 **알림 메시지**, ⑦ 패자에게 **잃은 총량** 표시.

**결론부터: 일곱 개 전부 구현 가능하다.** 서버(Cloud Functions) 없이 지금 구조 그대로 된다.
다만 ③은 **"한 명이 죽으면 판이 끝난다"는 현재의 대전제를 폐기**하는 변경이라,
멀티 전체에서 가장 큰 개조가 된다. 아래에 근거와 구체적인 방법을 적는다.

---

## 1. 왜 "눈으로 보이게" 가 쉬운가 — 계단이 이미 전원 동일하다

멀티는 **같은 시드**로 계단을 만든다(`GameScene.seed = room.seed`). 즉 내 클라이언트는
**상대가 서 있는 계단의 정확한 좌표를 이미 알고 있다.** 상대에게서 받아야 하는 건 층수 하나뿐이고,
그건 지금도 300ms마다 오고 있다(`publishProgress`).

`stairs.js:render()` 의 좌표 규칙이 그대로 재사용된다:

```
화면x = xs[상대층] - camX + CENTER_X - 16
화면y = CHAR.footY - (상대층 - 내층) × STAIR.gapY     // gapY = 20
```

- **세로**로는 내 층 기준 대략 **-6 ~ +12층**이 화면 안이다(footY 212, VIEW_H 320).
- **가로**는 무작위 보행이라 층 차가 크면 화면 밖으로 나간다(층당 ±30px).

그래서 표시를 **세 겹**으로 둔다.

| 상대 위치 | 표시 |
|---|---|
| 화면 안 | **반투명 고스트 캐릭터** + 머리 위 작은 이름표(이름·층수) |
| 세로는 보이는데 가로가 밖 | 좌/우 가장자리에 **화살표 + 이름 + 층수** |
| 세로도 밖 | 화면 오른쪽 **레이스 바**(세로 미니 트랙)에 점으로 |

레이스 바는 항상 보이므로 "지금 누가 앞이냐"가 한눈에 들어온다 — 역전 체감의 핵심이다.
고스트는 `globalAlpha`(0.5~0.6)만 쓰고 **좌표는 정수**라 §3-1 픽셀 규칙을 깨지 않는다
(스무딩이 아니라 알파 블렌딩이다).

## 2. "상대 아이디 글씨가 크다" — 원인은 폰트가 하나뿐이라서

지금 인게임 글자는 **갈무리11 하나**다(`font.generated.json`, 글리프 높이 11px).
`multiHud` 는 이미 `scale: 1` 로 그리고 있으므로 **더 줄일 방법이 없다.**

→ **갈무리7을 두 번째 폰트로 굽는다.** `galmuri` 패키지에 `Galmuri7.ttf` 가 이미 들어 있다.
`tools/build-font.mjs` 를 크기 인자로 일반화해 `font7.generated.json` 을 추가로 만들면
상대 이름·판돈·알림 문구를 **11px → 7px** 로 낮출 수 있다. 세 명분이 한 줄에 들어간다.

### 같이 드러난 진짜 버그 — **인게임 상대 이름이 '?'로 나온다**

폰트는 **코드 문자열에 등장하는 한글만** 굽는다(§3-1). 그런데 닉네임은 사용자가 지은 글자다.
실측:

```
아:O 빠:O 게:O 임:O 왕:O   ← 우연히 코드에 있던 글자
닙:X 스:O 리:O 안:O 토:X   ← 없는 글자 = 화면에 '?'
```

즉 지금 배포본에서 `토토` 는 **`??`** 로, `닙스아리안` 은 **`?스아리안`** 으로 보인다.
(로비·대기방은 DOM+CSS라 멀쩡하고, **인게임 캔버스만** 이렇다.)

해결: **KS X 1001 상용 한글 2,350자**를 7px 폰트로 구워 별도 파일로 두고
**멀티 진입 시에만 동적 import** 한다. 용량 추정 — 현재 11px 386자가 26KB(글리프당 68B),
7px는 글리프당 30~40B 예상 → 2,350자 ≈ **80~95KB(원본), gzip 20~25KB**.
멀티 경로 전용이라 싱글 플레이어의 초기 로딩에는 영향이 없다.

캐릭터 아이콘은 `characters/<id>_front.png`(35×50)의 **머리 부분을 정수 ½로 축소**해
`face16.png` 를 굽는다(새 tools 스크립트). 상대 줄에 7px 이름 + 16px 얼굴이면 한 줄 12px 안에 들어간다.

## 3. 부활 베팅 — 데이터 모델과 판정

### 3-1. 방에 추가되는 필드 (RTDB)

```
players/$uid/
  revives : number   부활 횟수 (0~)          ← 신규
  deadAt  : number   죽은 시각(서버 보정)     ← 신규
  out     : boolean  부활을 포기했다          ← 신규
result/
  given/$uid : number[]   ← 이미 있음. **판돈 항아리로 재사용한다**
```

규칙(`docs/rtdb-rules.json`)도 같이 고쳐야 한다. `$other: false` 라 **필드를 추가하지 않으면
쓰기가 통째로 거부된다** — 예전에 이 함정으로 멀티가 죽은 적이 있다(§9-0-14).
그리고 `given/$uid` 의 개수 상한을 `!newData.hasChild('4')`(4개) → **200개**로 올려야
20켤레 베팅이 여러 번 쌓인다.

### 3-2. 판이 끝나는 조건 (대전제 교체)

| | 지금 | 바뀐 뒤 |
|---|---|---|
| 한 명이 죽으면 | **전원 즉시 종료** | 그 사람만 20초 부활 대기, 나머지는 계속 |
| 판 종료 | 첫 사망 | **살아 있는 사람이 0명이고, 죽은 사람 전원이 부활 창을 넘겼거나 포기(`out`)했을 때** |

누구든 그 조건을 관측한 클라이언트가 `finalizeResult` 를 부른다(먼저 쓴 사람 것만 남는 구조는 그대로).
`deadAt` 은 서버 보정 시각을 쓰므로 폰 시계가 달라도 20초가 같다(§9-0-22에서 오프셋 캐시를 이미 만들어 뒀다).

### 3-3. 부활 절차 (원자성이 핵심)

1. 방을 읽어 **1위 층수** `maxFloor` 확인
2. 내 지갑에서 20켤레 **먼저 차감**(`pickPenaltyShoes` 재사용, 티어 무관 랜덤)
3. `result/given/<나>` 에 그 20개를 **append** → 실패하면 **지갑 복구**
   (지금 정산이 쓰는 순서와 동일하다 — 올린 뒤 죽으면 복제, 반대면 손해라서 이 순서다)
4. `players/<나>` 에 `{ alive:true, stairs: maxFloor + 20, revives: +1, deadAt: null }`
5. 내 `GameScene` 을 `startFloor = maxFloor + 20` 으로 되살린다(엘리베이터가 쓰는 경로 그대로)

상대 화면에는 `given` 이 커진 것과 `revives` 증가가 같이 보이므로
**"OO님이 신발 20켤레를 걸고 20칸 앞으로 부활했습니다"** 를 띄운다.

### 3-4. 판돈과 정산

- **판돈 = `given` 에 실제로 들어 있는 켤레 수 + 아직 안 낸 기본 1켤레 × 인원**
  화면 문구: `이 게임에 걸린 신발 000켤레` (하단 고정)
- **표시를 `revives` 로 계산하지 않는 게 중요하다.** 조작된 클라이언트가 `revives` 만 올려도
  **항아리에 실제로 없는 신발은 아무도 못 받는다.** 표시와 실물이 항상 일치한다.
- 판이 끝나면 **1위가 `given` 전부를 걷는다**(자기가 냈던 부활 비용도 되돌려받는다).
  지금의 `settled` 비트마스크를 **패자 목록이 아니라 순위 전체**에 대해 돌리면 그대로 재사용된다.
- 패자 문구: **"이번 게임에서 신발 N켤레를 잃었습니다"** — N = 1(기본) + 20 × 내 부활 횟수.

### 3-5. 순위 판정

부활이 생기면 "신발 많이 주운 사람" 기준은 의미가 옅어진다(부활하면 20칸을 그냥 얻으니까).
제안: **① 살아남은 사람 → ② 계단 높은 사람 → ③ 주운 신발 → ④ 먼저 도달**.
지금은 ①이 없고 신발이 1순위다. **이건 기획 결정이라 확인이 필요하다.**

## 4. 새로 생기는 위험과 대비

| 위험 | 왜 생기나 | 대비 |
|---|---|---|
| **판돈 증발** | 판 도중 전원이 나가면 방이 지워지는데 `given` 에 이미 낸 부활 비용이 들어 있다 | `mustKeepRoom` 이 **순위가 없어도 `given` 이 있으면** 방을 보존하도록 확장 |
| **부활 무한 루프** | 신발만 있으면 계속 부활 → 판이 안 끝난다 | 그게 기획 의도지만, **판당 최대 부활 횟수**(예: 인당 5회)와 **최대 판 시간**을 balance.js 에 두는 것을 권한다 |
| **가난한 사람은 못 논다** | 20켤레가 없으면 부활 불가 | 버튼을 비활성 + 이유 표기("신발 20켤레가 필요합니다 — 현재 7켤레"). 참가 최소치(2켤레)는 그대로 |
| **조작 클라이언트** | 안 내고 부활하거나 층수를 부풀림 | 지금과 같은 신뢰 수준. 다만 **받는 건 항아리에 실제로 있는 것뿐**이라 이득이 없다 |
| **20초 대기가 지루함** | 죽은 사람이 20초를 본다 | 대기 화면에 **상대 진행 상황을 계속 보여 준다**(고스트·레이스 바 그대로). 남은 시간·판돈·부활 버튼이 한 화면에 |
| **대기자(waiting) 처리** | 판이 길어지면 대기자가 오래 기다린다 | 지금 로직 유지(다음 판부터 참가). 판 시간 상한이 그래서 필요하다 |

## 5. 단계별 계획 (배포 단위)

**1단계 — 보는 재미 (규칙 변경 없음, 되돌리기 쉬움)**
1. 갈무리7 폰트 굽기 + 상용 한글 2,350자(멀티 전용 동적 import) → **인게임 이름 '?' 버그 동시 해결**
2. 캐릭터 얼굴 아이콘 16×16 굽기
3. 상대 줄 재설계: `[얼굴][이름 7px][층수·신발]`
4. 고스트 캐릭터 + 가장자리 화살표 + 레이스 바
5. 낙사 알림 티커("OO님이 계단에서 떨어졌습니다")

**2단계 — 베팅·부활 (여기서 규칙 재게시 필요)**
6. 규칙: `revives`·`deadAt`·`out` 추가, `given` 상한 200, 초기화 허용 확장
7. 사망 → **20초 부활 오버레이**(타이머·판돈·[나가기]/[부활하기])
8. 부활 절차(차감 → 항아리 → 위치 점프) + 실패 시 복구
9. 판 종료 조건 교체 + 순위 판정 교체
10. 정산: 1위가 항아리 전부 수거 / 패자 "N켤레 잃었습니다"
11. 하단 판돈 표시 + 부활 알림 티커
12. QA: `qa:multi` 에 **판돈 보존·이중 수령 금지·부활 비용 정확도** 묶음 추가

**3단계 — 손맛**
13. 역전 순간 연출(화면 플래시·효과음), 부활 시 등장 이펙트, 판돈이 커질 때 숫자 강조

1단계는 지금 코드 위에서 바로 가능하고, 2단계는 `GameScene`·`multiplayer.js`·`multiSettle.js`·
규칙을 함께 고쳐야 하므로 **한 번에 배포**해야 한다(중간 상태로 배포하면 구버전과 신버전이
같은 방에서 만나 판정이 갈린다). 구버전 호환을 위해 방에 `mode: 'battle'` 표시를 넣고
**구버전 클라이언트는 그 방에 못 들어오게** 막는 것을 권한다.

## 6. 확인이 필요한 기획 결정

1. **순위 기준**을 "살아남음 → 계단"으로 바꾸는 것 (지금은 신발 우선)
2. **부활 비용 20 / 앞지르기 20칸**을 고정으로 둘지, 난이도·인원별로 다르게 할지
3. **부활 횟수 상한**과 **판 최대 시간** (무한 부활 방지)
4. 4인전에서 **2등·3등도 기본 1켤레만** 잃는지(지금 규칙) — 부활 비용은 별도로 이미 낸 상태

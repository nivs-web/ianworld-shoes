# 드래곤 스트라이커 결투 — 다시 기획 (2026-08-27)

> 사용자 지적: *"멀티 한판 해봤는데 뭐가 멀티플레이인지 모르겠다."*

맞는 지적이다. 지금 결투는 **멀티가 아니다.**

---

## 0. 지금 무엇이 잘못돼 있나

| | 지금 | 있어야 하는 것 |
|---|---|---|
| 세상 | 둘이 **각자 다른 판**을 뛴다 | 같은 맵 |
| 상대 | **안 보인다.** 1초마다 숫자만 오간다 | 한 화면에 같이 나온다 |
| 겨루는 값 | 보스 처치 수 | 금화 · 생존 |
| 죽으면 | 나만 끝, 상대는 계속 | **둘 다 끝** |
| 상금 | 판돈 400 + 각자 주운 금화 | 판돈 + **둘이 주운 금화 전부** |
| 한 판 더 | **로비로 튕긴다** | 대기방으로 |

즉 지금은 "따로 한 판씩 뛰고 점수표를 비교하는 것"이다.
같이 노는 느낌이 없는 것이 당연하다.

---

## 1. 왜 lockstep(완전 결정론)을 안 쓰는가

같은 씨앗으로 두 클라이언트가 **똑같이** 시뮬레이션하면 아무것도 주고받을 필요가
없다. 신발게임의 계단이 그 방식이다(`MULTI_BATTLE_PLAN.md` §1).

드래곤에서는 **안 된다.** 이유가 둘이다.

1. **난수가 122곳**이다. 적 생성뿐 아니라 적의 매 프레임 움직임(19곳), 파티클,
   날씨, 아이템 낙하까지 흩어져 있다. 하나만 놓쳐도 두 세상이 조용히 갈라진다.
   "조용히" 가 문제다 — 터지지 않고 **서서히 달라져서** 누가 이겼는지가 갈린다.
2. **프레임이 같지 않다.** 고정 스텝(1/60)을 쓰지만 `MAX_STEPS = 5` 로 잘린다.
   한쪽 폰이 잠깐 버벅이면 그 순간 시뮬레이션 걸음 수가 달라진다.
   씨앗으로는 절대 못 막는 종류의 어긋남이다.

lockstep 은 **한 번 어긋나면 조용히 계속 틀린다.** 겨루는 게임에서 그건
"내 화면에서는 내가 먹었는데 상대 화면에서는 상대가 먹었다" 로 나타난다.
가장 나쁜 종류의 버그다.

## 2. 그래서 — **다투는 것만 공유한다**

세상을 둘로 가른다.

| | 어떻게 | 왜 |
|---|---|---|
| **금화** | 씨앗으로 정해진 자리·시각에 뿌린다. 먹으면 그 번호를 방에 올린다 | **겨루는 대상**이다. 여기만은 두 화면이 정확히 같아야 한다 |
| **상대 용** | 10Hz 로 자리·생사·불레벨을 올린다. 반투명 고스트로 그린다 | "같이 있다" 는 느낌의 전부 |
| 적 | 같은 씨앗으로 **같은 파도**를 부르되 픽셀까지 맞추지 않는다 | 압박을 주는 역할이다. 한 칸 어긋나도 게임이 안 갈린다 |
| 파티클·날씨 | 각자 | 볼거리다 |

### 2-1. 금화를 적이 떨어뜨리지 않는다 (결투 한정)

싱글에서 금화는 적을 잡으면 나온다. 결투에서 그대로 두면 **적이 어긋나는 순간
금화 자리도 어긋난다** — 겨루는 대상이 두 화면에서 다른 곳에 있게 된다.

결투에서는 금화를 **씨앗이 정한 비**로 바꾼다.

```
coinAt(n) = { t: 0.8n + rnd(0.4), y: rnd(120..600), big: n % 17 === 0 }
```

`n` 번째 금화는 두 화면에서 **같은 시각 같은 자리**에 뜬다. 번호가 있으니
"이건 내가 먹었다" 를 한 숫자로 말할 수 있다.

부수 효과가 좋다 — 결투가 **"금화 쟁탈"** 이라는 제 얼굴을 갖는다.
적은 방해물이 되고, 금화 비를 누가 더 잘 훑느냐가 승부가 된다.
사용자가 말한 *"서로 금화를 많이 먹겠다고 다투는 게임이 주요 목표"* 가 이것이다.

### 2-2. 동시에 먹으면

지연이 100~300ms 라 **완벽한 심판은 없다.** 규칙을 미리 정한다:

> **동시에 닿으면 둘 다 먹는다.**

빼앗기는 쪽으로 정하면 "분명히 내가 먼저 닿았는데 사라졌다" 가 생긴다.
둘 다 주는 쪽은 아무도 억울하지 않고, 겹치는 일은 드물다.
그리고 어차피 **1등이 전부 가져가므로** 총량이 조금 늘어도 승부가 안 뒤집힌다.

## 3. 규칙

### 3-1. 판이 끝나는 조건

> **한 명이 죽으면 둘 다 끝난다.** (사용자 지정)

죽은 사람이 곧 진 사람이다. 그래서 결투는 **"먼저 죽지 않기"** 가 1순위,
**"죽기 전까지 금화 많이 먹기"** 가 2순위인 게임이 된다.
시간(300초)이 다 되면 그때는 금화로 가른다.

### 3-2. 순위

```
① 살아남았는가        (죽은 사람이 진다)
② 금화                 (많이 먹은 사람이 이긴다)
③ 점수
④ uid                  (비기는 경우를 남기면 둘이 다른 답을 낸다)
```

예전의 "보스 처치 수" 를 뺀다 — 결투가 겨루자는 값이 금화로 바뀌었다.

### 3-3. 상금

> **1등이 판돈 전부 + 둘이 주운 금화 전부를 가져간다.** (사용자 지정)

```
상금 = 판돈 200 × 2  +  (내가 주운 금화 + 상대가 주운 금화)
```

진 사람은 건 200 과 자기가 주운 금화를 전부 잃는다.
그래서 지고 있을 때도 **금화를 계속 주울 이유**가 있다 — 역전하면 그게 다 내 것이 된다.
지는 쪽이 마지막까지 포기하지 않는 것이 이 규칙의 목적이다.

## 4. 주고받는 것 (RTDB)

```
rooms/$code/
  seed                        ← 이미 있다. 금화 비와 적 파도가 이걸로 정해진다
  players/$uid/
    x, y      number          ← 신규. 판 좌표 (0~1280, 0~720)
    lv        number          ← 신규. 불레벨 (고스트를 제 모습으로 그리려고)
    coinsTook number          ← 신규. 내가 먹은 금화 **번호의 최댓값**
    alive     boolean         ← 이미 있다
    coins     number          ← 이미 있다
```

★ **규칙(`docs/rtdb-rules.json`)을 같이 고쳐야 한다.** `$other: false` 라
**필드를 새로 넣으면서 규칙을 안 고치면 쓰기가 통째로 거부된다.**
예전에 이 함정으로 멀티가 죽은 적이 있다.

### 4-1. 먹은 금화를 왜 "번호의 최댓값" 하나로 보내는가

번호 목록을 다 보내면 300초에 수백 개가 쌓인다. 대신 **비트 묶음**을 쓴다:

```
took: [ ...32비트 정수... ]   ← 번호 n 은 took[n>>5] 의 (n&31) 번째 비트
```

300초 동안 금화가 400개쯤이면 13개 정수면 된다. 갱신은 10Hz.
받는 쪽은 자기 화면의 금화 중 그 비트가 켜진 것을 지운다.

## 5. 결과창

신발 멀티 결과창(`MultiResult.js`)의 뼈대를 그대로 가져온다:

```
깃발 → 큰 문구 → 작은 문구 → 숫자 줄 → 순위표 → [한 판 더] [로비로]
```

드래곤에 맞게 바꾸는 것:

- 숫자 줄 : `이긴 사람이 가져간 금화 0,000` / `이번 판에서 잃은 금화 000`
- 순위표 한 줄 : `[순위][용 초상][이름][금화 000][점수 0,000]`
- **보유 금화 총량**을 아래에 한 줄 (*"보유한 금화 총 수량을 보여준다거나"*)

### 5-1. "한 판 더" 가 로비로 튕기던 것

`onLeave` 가 **무조건** `leaveRoom(code)` 를 부르고 있었다. 그래서 한 판 더를
누르면 방에서 빠지면서 스택도 같이 빠져 로비까지 밀려났다.

신발 쪽은 이미 답을 갖고 있다 — `keepSeat` 깃발을 세우고
`resetRoom` 뒤에 `nav.replace(WaitingRoom)` 로 간다. 같은 방식을 쓴다.

## 6. 단계

**1단계 — 규칙과 결과창** (지금 코드 위에서 바로 된다)
1. 한 명 죽으면 둘 다 끝
2. 순위 = 생존 → 금화 → 점수
3. 1등이 판돈 + 둘이 주운 금화 전부
4. 결과창을 신발 뼈대로 다시 짓기 + 보유 금화 총량
5. **한 판 더 → 대기방** (로비 튕김 수정)

**2단계 — 같이 있다** (규칙 재게시 필요)
6. RTDB 에 `x, y, lv, took` 추가 + 규칙 게시
7. 10Hz 로 내 자리 올리기
8. 상대를 반투명 고스트 + 이름표로 그리기
9. 상대가 죽는 순간 화면에 알림

**3단계 — 금화 쟁탈**
10. 결투에서 금화를 **씨앗 비**로 바꾸기 (번호 붙임)
11. 먹은 번호를 비트로 올리고, 상대가 먹은 것은 내 화면에서 지우기
12. 화면 위에 **금화 점수판** (`나 000 : 000 상대`) 고정

**4단계 — 손맛**
13. 역전 순간 연출, 상대가 코앞에서 채 갔을 때의 반응
